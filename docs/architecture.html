학생이 “월요일 오전에 듣는 3학점 전공필수 알려줘”처럼 물으면, 백엔드가 질문을 PostgreSQL SELECT 문으로 바꿔 실행하고 결과를 강의 목록과 시간표에 보여줍니다. 이 문서는 화면에서 DB까지 질문 하나가 지나가는 경로와 각 모듈의 역할을 정리합니다.

01

시스템 구성

React 화면, FastAPI 백엔드, 원격 GPU의 Ollama, PostgreSQL, Redis Stack 다섯 덩어리로 나뉩니다. 개발 환경에서는 Docker Compose가 Ollama를 뺀 네 개를 띄웁니다.

클라이언트 애플리케이션 서버 모델 데이터 저장소

실선은 v2 경로, 점선은 v1에서만 쓰는 경로입니다. v1도 Ollama와 PostgreSQL을 쓰지만 그림에서는 생략했습니다. Redis는 v1 벡터 캐시에만 쓰이므로 없어도 v2는 동작합니다.

02

질문 하나의 요청 흐름

챗 팝업에서 보낸 질문은 POST /api/v1/chat/query로 들어와 _run_query()에서 파이프라인이 정해집니다.

투표 결과가 비거나 실패하면 Ollama 호출과 실행이 한 번 더 반복됩니다(04장의 ⑧ 재시도).

응답 형식

{
  "sql": "SELECT * FROM v_course_info WHERE ... LIMIT 50",
  "data": [ { "subject_name": "...", "professor": "...", ... } ],
  "error": null,
  "rejected": false,            // 모호하거나 답할 수 없는 질문이면 true
  "candidates": [ { "index": 0, "sql": "...", "rows": 12, "error": null, "rejected": false } ],
  "timings_ms": { "preprocess_ms": …, "llm_ms": …, "execute_ms": …, "total_ms": … },
  "value_candidates": [ { "column": "dept_name", "value": "컴퓨터융합학부", "source": "ner" } ]
}

로그인하지 않은 학생이 아래 질문을 보냈을 때, v2 파이프라인이 문장을 SQL과 결과로 바꿔 가는 과정을 단계별로 재생합니다. 단계를 누르면 그 장면에서 멈춥니다.

  AND day_of_week = '월'

    04

    v2 파이프라인

    backend/t2s/pipeline.py의 run_v2()가 여덟 단계를 순서대로 돌립니다. 단계를 눌러 세부 내용을 보세요.

    설계 원칙

    • 모델은 SQL만 쓴다. 로그인 학생 조건, 이수 과목 제외, 행 수 제한, 시간표 행 확장은 모두 실행 직전 코드가 결정적으로 붙입니다.
    • 거부도 정답이다. 스키마로 답할 수 없거나 다른 학생 정보를 묻으면 모델이 UNKNOWN을 내고, 응답은 rejected: true가 됩니다.
    • 설정은 호출 시점에 읽는다. load_settings()가 매 요청 환경변수를 읽어 평가 스크립트가 후보 수·예시 사용 등을 바꿔가며 비교할 수 있습니다.
    • 의존성 주입. Deps로 전처리·chat·run·validate를 갈아끼울 수 있어 DB·Ollama 없이 단위 테스트가 돕니다(t2s/tests/ 11개 파일).
    05

    SQL 안전장치

    생성된 SQL은 backend/validate.py의 validate_generated_sql()이 sqlglot AST로 검사한 뒤에만 실행됩니다. 실행 자체도 읽기 전용입니다.

    • 1
      SELECT 한 문장만 허용. WITH(CTE)는 생성 형식 오류로 따로 표시합니다.
    • 2
      함수 허용 목록. pg_read_file, set_config, pg_sleep 같은 시스템 함수는 목록에 없어 거부됩니다. U& 문자열, $ 인용, 단독 TABLE, 행 잠금도 거부합니다.
    • 3
      학생 데이터 범위 검사. student·enrollment를 쓰는 모든 인스턴스는 student_id = %(student_id)s로 묶여 있어야 합니다. 비로그인 사용자가 개인 테이블을 건드리면 실행 전에 거부됩니다.
    • 4
      값 바인딩. 학번은 SQL 문자열에 넣지 않고 psycopg2 파라미터 %(student_id)s로만 전달합니다.
    • 5
      실행 제한. default_transaction_read_only=on, statement_timeout=3000ms, 결과 LIMIT 50(T2S_ROW_CAP).
    주의v1 경로의 db.run_query는 아직 읽기 전용 연결이 아닙니다. 서비스는 v2로 돌고 있지만 v1을 켤 때는 이 차이를 기억해야 합니다.
    06

    v1 레거시 파이프라인

    T2S_PIPELINE=v1(코드상 기본값)일 때 쓰는 backend/process.py의 process()입니다. 미세조정 모델 text2sql-local과 Redis 벡터 캐시를 중심으로 만들어졌습니다.

    1. 전처리·마스킹
    keyword_extract.preprocess_query

    NER로 개체를 찾아 교정하고, 값을 <DEPARTMENT> 같은 자리표시자로 바꾼 마스킹 질의를 만듭니다.

    2. 벡터 캐시 조회
    vector_cache.find_vector_cache

    마스킹 질의를 KURE-v1로 임베딩해 Redis에서 유사도 0.9 이상 항목을 찾고, 있으면 자리표시자에 값을 채워 SQL을 재사용합니다.

    3. 생성·검증·실행
    llm.py · validate.py · db.py

    캐시가 없으면 LLM으로 생성하고 검증 후 실행, 오류 시 자기수정 재시도. 성공한 SQL은 마스킹해 캐시에 저장합니다.

    평가셋 243건 기준 정확도는 16.5%였습니다. v2는 같은 평가셋에서 이를 90.1%까지 끌어올렸고, 지금 서비스 설정(backend/.env.example, docker-compose.yml)은 v2입니다.

    09

    데이터 모델

    강의 질문 대부분은 조인을 미리 풀어둔 뷰 v_course_info 하나로 답합니다. 개인 질문만 student·enrollment를 씁니다.

    객체종류주요 컬럼

    설정과 배포

    docker compose up --build로 frontend·backend·postgres·redis를 띄웁니다. Ollama는 컨테이너 밖(원격 GPU 서버)에 있고, 스키마와 데이터는 직접 넣어야 합니다.

    환경변수현재 값의미
    T2S_PIPELINEv2질의 파이프라인 선택 (코드 기본값은 v1)
    T2S_MODELqwen2.5-coder:14b-instructv2 생성 모델. 없으면 OLLAMA_MODEL
    T2S_CANDIDATES1후보 SQL 수. 5개는 +1.6%p에 지연 약 3배
    T2S_TEMPERATURE0.4후보 생성 온도 (재시도는 0)
    T2S_EXAMPLES_K4few-shot 예시 수. 끄면 정확도 52.7%로 하락
    T2S_VALUE_SOURCESner,ngram값 후보 출처
    T2S_ROW_CAP50결과 행 상한
    T2S_STATEMENT_TIMEOUT_MS3000쿼리 실행 제한 시간
    T2S_MAX_TOKENS256생성 토큰 상한
    T2S_REVIEW_LOG1질의·SQL을 t2s/logs/review_queue.jsonl에 기록
    OLLAMA_BASE_URL원격 서버Ollama 주소 (Compose에선 host.docker.internal도 가능)
    DATABASE_URL환경별없으면 강의 목록은 mock, 질의는 오류
    REDIS_URL · VECTOR_CACHE_*선택v1 벡터 캐시 (임계 0.9, TTL 86400초)
